ERP: expected runs prevented

ERP = Expected Runs Prevented on the next pitch. Here this means the expected reduction in batting run expectancy: ERP = −expected batting run change. Positive ERP means an expected reduction in scoring opportunity; negative ERP means an increase. This is our project’s forecast definition, not an official MLB statistic or measured causal runs saved.

A pitch changes scoring opportunity through balls, strikes, contact, walks and other outcomes. First estimate the probability of each outcome in this hitter/count/runner/out/history situation. Then multiply each by its batting run impact and add. Negating that expected batting run change gives ERP.

Expected batting run change = Σ outcome probability × batting run impact ERP = −expected batting run change Improvement over usual mix = ERP(candidate) − ERP(usual mix)

Higher ERP is better. ERP is not forced to zero for a single candidate and can be negative even for the leading pitch. If every supported candidate has negative ERP, #1 is the smallest projected increase in batting scoring opportunity. Negative values are retained rather than clipped away.

Illustrative example: fastball expected batting run change −0.010, slider +0.020. Their ERP values are +0.010 and −0.020 runs/pitch, respectively: +1.00 and −2.00 runs per 100 equivalent situations. At a usual mix of 60% fastballs and 40% sliders, mix ERP is −0.002 runs/pitch. The fastball’s improvement over that mix is +0.012 runs/pitch, or +1.20 runs/100. That improvement is a separate comparison, not ERP.

The usual mix uses this pitcher’s observed 2026 count/hand frequencies, normalized over supported choices. With one candidate, improvement over mix is zero, but ERP can still be positive or negative. The average-history view weights reachable histories using that pitcher’s observed frequencies; the exact-history view uses the selected previous pitch and result.

ERP’s common run-expectancy scale permits like-for-like comparisons for the same hitter and state, but it is not an overall pitcher ability rating or a bullpen deployment recommendation. “Per 100” is a rescaling across equivalent situations, not a game or season runs-saved projection. Tiny runner-up gaps are close options, with a display heuristic of 0.001 runs/pitch rather than a statistical confidence interval.

Probabilities use a shared model with separate pitcher profiles and repertoires. Current-pitch measurements and current-date outcome summaries are excluded from pre-pitch inputs. Run impacts use recorded Statcast delta_run_exp, pooled by count/base/out/outcome with smoothing strength 20. The broad out class pools fielder’s choices, double plays and sacrifices; advancement risk is therefore approximate.

Pitch choice and execution are observational. Location intent, catcher calls and selection effects remain uncontrolled. ERP is not ERA, actual saves, total inning runs prevented or win probability. It does not optimize walk-off risk, protecting a lead, fatigue or pitcher availability. Recompute after each result rather than following a fixed script.
